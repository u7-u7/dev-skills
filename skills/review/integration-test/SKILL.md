# 集成测试用例生成

## 技能关系

本技能是**组合技能**，调用以下基础技能：
- ✅ `author-final-review` - 生成前三章（基本信息、变更说明、影响面分析）
- ➕ `integration-test 独有部分` - 第四章测试用例清单（P0/P1用例 + 覆盖度追溯表）

## 依赖检查

本技能依赖同仓库的 `skills/review/author-final-review`。

执行前必须确认依赖技能可用；若缺失，停止执行并提示用户从本仓库恢复或安装 `author-final-review`。

## 调用流程

1. 调用 `author-final-review` 完整流程 → 获得前三章（基本信息、变更说明、影响面分析）
2. 基于前三章输出 → 进行风险驱动用例设计 → 生成第四章测试用例清单
3. 合并输出单一报告文件

---

## 角色定位

你是一位资深的测试架构师,负责基于代码变更生成 Dubbo 集成测试用例文档。

## 核心指导原则

- **范围明确**:严格聚焦于提供的代码,提供具体、可操作的用例
- **上下文驱动**:主动分析调用方、被调用方,确保用例有充分依据
- **风险驱动**:基于 review-report 的风险评估,优先覆盖高风险场景

## 执行流程

### Step 0: 读取关联文件

读取 [references/review-report.md](references/review-report.md) 完整内容,确保后续步骤严格按其格式输出第一~三章。

### Step 1: 执行审查报告基础流程

> 调用 `author-final-review` 技能的完整流程（Phase 1-4）
>
> 详见：[author-final-review/SKILL.md](../author-final-review/SKILL.md)
> 或直接参考：[references/review-report.md](references/review-report.md)

**输入**: git diff / git status
**输出**:
- 第一~三章正文（按 review-report.md 模板）
- 风险评估表（❗/⚠️/👀）
- 核心影响点明细表
- 兼容性声明

**注意**: 严格按 review-report.md 的 Phase 1-4 执行，不得跳过任何步骤

**输入**: 当前分支代码变更(git diff / git status)

**行动**: 严格按 review-report.md 执行 Phase 1 ~ Phase 4

**输出**(供后续 Step 使用):
- 第一~三章正文(按 review-report.md 模板)
- 变更主题列表
- 风险评估表(❗/⚠️/👀)
- 核心影响点明细表
- 兼容性声明(如有)

### Step 2: 风险驱动用例设计

**前置条件**: Step 1 完成

**行动**:

1. **提取关键信息**:
   - 风险等级(❗/⚠️/👀)决定测试深度
   - 核心影响点明细表 -> P0 用例必须覆盖
   - 风险评估表 -> 每个❗/⚠️风险点必须有对应验证用例
   - 兼容性声明 -> 新旧兼容验证用例

2. **按用例优先级定义识别场景**:
   - P0:核心流程、副作用验证、兼容性验证、风险覆盖
   - P1:边界条件、异常场景

3. **按用例生成规则编写用例**

4. **用例与变更映射**:确保每个关键改动都有用例覆盖

**输出**: 测试用例清单 + 覆盖度追溯表

### Step 3: 汇总输出

**前置条件**: Step 2 完成

**行动**: 按输出模板合并为单一报告文件

**输出**: `.doc/{分支名}/integration-test-{YYYYMMDD-HHmmss}.md`

### Step 4: 自检与回退(不通过则丢弃并重写)

#### 格式自检
- 以输出模板为唯一标准
- 第一~三章:引用 review-report.md 的模板输出
- 第四章:引用本技能的模板输出
- 命中任一禁项(新增章节/过程解释/推测性结论/百科式长清单)=> 丢弃并重写

#### 覆盖度自检(关键)
- **风险覆盖**:每个❗/⚠️风险点都有对应 P0 用例
- **影响点覆盖**:核心影响点明细表中每个影响点都有验证用例
- **追溯表完整**:覆盖度追溯表中所有项均为✅已覆盖

#### 用例质量自检
- **可执行性**:P0 用例的 JSON 入参可直接用于测试
- **验证点明确**:每个用例的预期结果具体可验证
- **幂等验证**:涉及写操作的 P0 用例包含幂等性验证点

## 用例优先级定义

| 级别 | 定义 | 覆盖范围 | 失败影响 |
|:-----|:-----|:---------|:---------|
| **P0** | 核心流程 | 主干业务路径、关键副作用、兼容性 | 阻断发布 |
| **P1** | 边界异常 | 边界条件、异常场景、降级路径 | 需评估后发布 |

## 用例生成规则

- **P0 用例**:Dubbo 接口 + 场景 + 完整 JSON 入参 + 预期 JSON 出参 + 验证点 + 副作用验证
- **P1 用例**:Dubbo 接口 + 场景 + 预期结果(相似边界/异常合并)
- 除 Dubbo 接口全限定名外,所有 Java 类/方法只输出短名
- 若变更无 Dubbo 入口:询问是否需要"测试专用 Dubbo 接口"

## 输出格式

### 输出文件
- **目录**: `.doc/{分支名}/`
- **文件名格式**: `integration-test-{时间戳}.md`
- **时间格式**: YYYYMMDD-HHmmss
